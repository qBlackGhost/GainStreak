Notes and open questions

  1. The siblings aren't sheets. On the phones, Settings › Email and Settings › Password both open the Account page (ProfilePage.Account), and their forms open inline in the Account card (IsEditingEmail / IsChangingPassword). Neither uses a Sheet. The spec asks for a sheet, so I drew one. It's built from the CalorieGoalSheetView frame, and its fields copy the Email form inside it. Confirm: a sheet (as drawn), or an inline form on the Account page like the siblings? Frame 1b shows where the tile would go in that case.
  2. Where the row sits. I put Username first in the ACCOUNT group (Username, Email, Password), because it's what you sign in with and what friends see. It could go after Password instead. On the Account page (1b) I put it first too.
  3. The current name shows as text in the same icon tile as the Account card's Email and Password, not as a read-only field. The row value and the tile show it without "@". Only the toast uses "@name", as the Friend QR sheet does.
  4. Capital letters during the wait. Capital-only changes are free (decision 2), so they could still be allowed during the 30 days. I drew the wait as fully disabled, as asked. The other option is to keep the field on and accept only a capitals-only change. Confirm which. Also, should the tester note stay visible while waiting? (It does in the drawing.)
  5. Offline is shown before you try. Today RenameNeedsConnectionMessage only comes back after a failed call (AccountService.cs:254). For the "button disabled" state, the sheet has to know it's offline when it opens (the session's offline flag). If you'd rather try and then show the message, it would sit above the button as a sheet-level error (TextBlock.error, 13 px), as in CalorieGoalSheetView.
  6. Live counter and check: no precedent. No screen has a character counter or a "valid" check today. Create account only shows the placeholder "Letters, digits, _ . -" and an error after you submit. To keep it minimal, I used one 12 px line under the field: the hint or the CheckUsername message on the left, and a mono counter on the right that turns lime when valid (orange at 32 / 32). You could drop the counter and keep only the message.
  7. The same name. The spec doesn't cover typing your current name. I drew a muted "That's your username now." with the button disabled. The wording is new.
  8. Error colour. Profile's field errors use TextBlock.fieldError from GymApplication.axaml:29, which is IndianRed (#CD5C5C) in both themes. It isn't the ErrorText token. I matched it. Should it move to ErrorText, which has light and dark values?
  9. Focus border. Profile's TextBox.field has no focus style, so the Fluent default would show. I drew the AccentInk focus border from AuthStyles.axaml (Sign in and Create account). Copy that style into the sheet?
  10. Saving state. No button in the app shows a spinner today. Other sheets just disable the button while IsSaving. I drew "Changing…" with a small spinner. Dropping the spinner and keeping the disabled "Changing…" would match better.
  11. Toast. The Map toast also has Undo and a close button. A rename can't be undone, so I left both out. Profile has no toast host today, so one would be added to the Profile view (or to MainView, over the screen).
  12. Field order and buttons. I used: current name, new name, password, tester note, then a full-width Change, with the close ✕ in the title row, as in the Calorie goal sheet. The account forms use a right-aligned Cancel + Save pair instead. Which pattern should win?
  13. Platforms. It's all shared GymApp.App code, so iOS and Android get the same sheet. Only the system keyboard differs. The desktop hides the row (the IPlatform gate in the spec). The TestBench's local mode gets it too.
